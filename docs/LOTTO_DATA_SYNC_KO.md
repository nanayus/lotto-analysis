# 로또 당첨 데이터 자동 동기화

## 데이터 출처

동행복권 홈페이지가 화면 표시를 위해 사용하는 다음 JSON 엔드포인트를 서버에서 조회합니다.

```text
https://www.dhlottery.co.kr/lt645/selectPstLt645Info.do
```

이 주소는 동행복권 도메인의 JSON 응답이지만, API 키·개발자 문서·별도 이용약관이 제공되는 공개 개발자 API로 확인된 것은 아닙니다. 운영 전 자동 조회와 앱 내 재게시 가능 여부를 동행복권에 문의하고 답변을 보관합니다.

앱이나 사용자 기기에서 동행복권을 직접 호출하지 않습니다. Firebase 예약 함수 한 곳만 저빈도로 호출하며 로그인, 쿠키, CAPTCHA, 접근 제한을 우회하지 않습니다.

## 서버 동기화

`syncLatestLottoDraw`가 매주 토요일 20:45(Asia/Seoul)에 실행됩니다.

- 결과가 아직 게시되지 않았으면 5분 이상의 간격으로 최대 6회 재시도
- 회차, 추첨일, 본번호 6개, 보너스 번호의 형식과 범위를 검증
- 같은 회차는 덮어써서 중복 실행에 안전하게 처리
- 누락 회차가 있으면 최대 12회까지만 순서대로 복구
- 과도한 누락이나 잘못된 응답은 자동 저장하지 않고 실패 로그로 남김

검증한 데이터는 Firestore의 `publicData/lotto` 문서에 저장합니다. 클라이언트는 읽기만 가능하고 쓰기는 Admin SDK를 사용하는 서버 함수에만 허용됩니다.

초기 배포 직후에는 Google Cloud Console의 Cloud Scheduler에서 생성된 작업을 한 번 수동 실행하거나 다음 예약 실행을 기다립니다.

## 앱 동기화

앱은 번들된 `lotto_history.json`을 오프라인 기준 데이터로 유지하고, 검증된 원격 회차를 합쳐 사용합니다.

- 일반 기간: 최대 12시간에 한 번 원격 확인
- 토요일 20시 이후와 일요일: 최대 15분에 한 번 원격 확인
- 앱 시작과 포그라운드 복귀 시 갱신 여부 확인
- 원격 데이터는 AsyncStorage에 저장
- Firebase 또는 네트워크 장애 시 번들 데이터로 모든 핵심 기능 유지
- 홈, 번호 생성, 번호별 통계, 종합 통계, 당첨번호 분석, 조합 분석이 같은 데이터 Provider 사용

이 방식은 EAS OTA 업데이트가 아니라 원격 데이터 동기화입니다. 새 회차를 반영하기 위해 앱 번들을 다시 배포하거나 앱을 재시작할 필요가 없습니다.

## 신규 회차 안내

새로 검증된 회차가 있을 때 다음 조건으로 홈에 바텀시트를 표시합니다.

- 해당 추첨 토요일 20:35 이후부터 일요일 23:59까지만 표시
- 회차별·기기별 한 번만 표시
- 제목: `제 N회 당첨 결과가 반영됐어요`
- 추첨일, 본번호 6개, 보너스 번호, `출처 동행복권` 표시
- 기본 행동: `이번 회차 분석하기`
- 보조 행동: `닫기`
- 닫기, 노출, 분석 이동을 Analytics 이벤트로 구분

이를 앱 버전 업데이트 팝업으로 표현하지 않습니다. 앱 업데이트 안내는 실제 코드 또는 네이티브 버전 업데이트가 필요한 경우에만 사용합니다.

## 배포 전 확인

```bash
npm --prefix functions run build
npm --prefix functions run lint
npm run typecheck
npm run lint
npm test -- --runInBand
firebase deploy --only firestore:rules,functions:account
```

Blaze 결제 계정과 Cloud Scheduler API가 필요합니다. Firebase 및 Google Cloud에서 예산 알림을 설정하고, Functions 실패 로그와 Firestore 읽기 수를 모니터링합니다.
