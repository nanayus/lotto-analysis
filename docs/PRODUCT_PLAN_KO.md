# Lotto Insight 제품 기획서

문서 버전: 2.0
작성 기준일: 2026-09-06
대상 제품 버전: 1.0.2
대상 플랫폼: iOS, Android, Mobile Web, Desktop Web
주요 카피: **번호는 무작위. 보는 방식은 다르게.**

---

## 1. 문서 목적

이 문서는 현재 저장소에 구현된 Lotto Insight의 v1 제품 범위와 출시 정책을 정의한다.

이전 문서의 `탐색 / 조합 만들기` 2개 탭 중심 MVP는 더 이상 현재 제품 구조를 설명하지 못한다. 현재 제품은 번호뽑기, 내번호보기, 통계보기, 콘텐츠의 4개 탭과 상단에서 진입하는 환경설정 화면으로 구성된다. 따라서 이 문서에서는 작은 기능 묶음으로서의 MVP 대신 **v1 핵심 출시 범위**를 기준으로 제품을 설명한다.

상태 표기는 다음과 같이 통일한다.

| 상태 | 의미 |
|---|---|
| v1 핵심 | 서버나 유료 상품 없이도 사용 가능한 첫 출시의 기본 경험 |
| v1 운영 | 첫 출시에서 운영할 수 있으나 외부 서비스 설정이 필요한 기능 |
| 단계적 활성화 | 코드가 존재하지만 기능 플래그, 스토어 상품 또는 서버 운영 준비 후 켜는 기능 |
| 후속 검토 | 현재 출시 범위 밖이며 별도 제품 결정이 필요한 기능 |
| 제외 | 제품 원칙상 제공하지 않는 기능 |

저장소의 실제 구현이 이 문서보다 우선한다. 구현과 문서가 다르면 먼저 현재 코드를 확인하고, 제품 의도가 필요한 차이는 결정 필요 사항으로 남긴다.

## 2. 제품 정의

### 2.1 한 문장 정의

대한민국 Lotto 6/45의 번호를 만들고 보관하며, 과거 추첨 데이터를 차분하고 직관적으로 탐색하는 모바일 중심 데이터 앱이다.

### 2.2 제품이 제공하는 가치

- 조건 없이 빠르게 번호를 만들 수 있다.
- 사용자가 원하는 형태 조건을 직접 정해 조합을 만들 수 있다.
- 생성하거나 직접 선택한 번호를 현재 기기에 보관할 수 있다.
- 한 번호, 전체 번호, 여섯 번호 조합을 서로 다른 관점에서 분석할 수 있다.
- 과거 통계를 미래 예측으로 오해하지 않도록 설명형 콘텐츠를 제공한다.
- 핵심 분석은 계정이나 유료 결제 없이도 사용할 수 있다.

### 2.3 제품 원칙

1. **분석이지 예측이 아니다.** 모든 수치는 과거 기록의 서술이다.
2. **번호 생성은 추천이 아니다.** 무작위 및 조건 생성은 입력 보조이며 확률 우위를 뜻하지 않는다.
3. **사용을 먼저 허용한다.** 핵심 기능 진입 전에 회원가입을 요구하지 않는다.
4. **핵심부터 상세로 읽힌다.** 요약에서 기록과 세부 통계로 단계적으로 이동한다.
5. **정확한 의미를 우선한다.** 본번호, 보너스 번호, 등수 기록을 혼동하지 않는다.
6. **차분하고 프리미엄하게 표현한다.** 복권·카지노의 전형적인 시각 언어를 피한다.

### 2.4 금지되는 메시지

- 당첨 확률이 높습니다
- 좋은 번호입니다
- 추천 조합 / 유리한 조합
- 당첨 예상 / 예측 번호
- 이 조합은 운이 좋습니다
- 등수 뒤에 별도의 완곡어를 붙인 표현

권장 표현은 `무작위 생성`, `조건에 맞춘 생성`, `과거 출현`, `과거 당첨 기록`, `1등–5등`, `선택한 기간 기준`이다.

## 3. v1 출시 범위

### 3.1 범위 요약

| 영역 | v1 핵심 | 운영 또는 활성화 조건 |
|---|---|---|
| 번호뽑기 | 랜덤조합, 조건 뽑기, 최신 회차, 추첨 카운트다운 | 없음 |
| 내번호보기 | 기기 저장, 즐겨찾기, 구매 표시, 재분석 | 없음 |
| 통계보기 | 번호별 통계, 종합 통계, 당첨번호 분석, 조합 분석 | 없음 |
| 콘텐츠 | 확률·무작위성·통계 해석 읽을거리 | 없음 |
| 환경설정 | 화면 모드, FAQ, 개인정보, 변경 내역 | 없음 |
| 이용 분석 | 화면·기능 이벤트 | Firebase Analytics 설정 필요 |
| 익명 식별 | 서버 요청과 구매 권한의 사용자 구분 | Firebase 설정 필요 |
| 광고·Pro | 결과 광고, 구독, 구매 복원 | 기능 플래그 및 운영 상품 필요 |
| AI 해설 | 확정 분석 스냅샷에 대한 설명과 질문 | Pro, Functions, 서버 Secret 필요 |
| 계정·클라우드 | Apple·Google 연결, 기기간 동기화 | 계정 연결 플래그와 Firebase 운영 필요 |
| 초대 코드 | Pro 이용 상태 반영 | 서버 및 운영 정책 필요 |

### 3.2 기본 배포 정책

기본 배포에서는 다음 정책을 사용한다.

- `EXPO_PUBLIC_PRO_PLAN_ENABLED=false`
- `EXPO_PUBLIC_RESULT_ADS_ENABLED=true`
- `EXPO_PUBLIC_ACCOUNT_LINKING_ENABLED=false`
- 핵심 생성·분석 기능 전체 공개
- 지원되는 네이티브 환경에서 결과 전면광고 운영
- Pro 결제 및 잠금 UI 비활성
- Apple·Google 계정 연결 UI 비활성
- 내 번호는 기기에 저장
- Firebase가 설정되어 있으면 익명 UID를 내부 식별자로 사용할 수 있음
- Firebase가 없거나 초기화에 실패해도 핵심 분석과 기기 저장은 계속 사용 가능

구독, AI, 클라우드는 코드베이스에 포함되어 있지만 현재 사용자에게 노출하지 않는다. 광고는 Pro와 독립된 플래그로 운영한다.

### 3.3 v1에서 제외되는 기능

- 당첨 예측 또는 당첨 확률 우위 점수
- AI가 번호를 직접 추천하거나 생성하는 기능
- 실제 복권 구매·발권 연동
- 푸시 알림
- 로그인 강제
- 사용자 간 공유 피드나 커뮤니티
- 분석 결과 자체의 별도 히스토리 시스템

```text
Lotto Insight
├─ 번호뽑기
│  ├─ 조건 뽑기
│  └─ 랜덤조합
├─ 내번호보기
│  ├─ 전체
│  ├─ 구매번호
│  └─ 즐겨찾기
├─ 통계보기
│  ├─ 번호별 통계
│  ├─ 당첨데이터 종합 통계
│  ├─ 당첨번호 분석
│  └─ 조합 분석
└─ 콘텐츠
   ├─ 콘텐츠 홈

   ├─ Pro 상태

   ├─ FAQ·개인정보처리방침
```

### 4.2 공통 하위 화면

- 번호별 출현 기록 상세
- 45개 번호 비교
- 회차별 당첨번호 분석
- 조합 분석 결과
- 전체/등위별 일치 기록
- 하위 조합 전체 목록
- 두 조합 비교
- 계정 및 데이터 삭제
- 인증 콜백

### 4.3 내비게이션 원칙

- 4개 탭은 서로 다른 사용 목적을 유지한다.
- 환경설정은 탭 바에 노출하지 않고 주요 탭의 공통 상단 설정·계정 버튼에서 진입한다.
- 번호 생성과 통계 탐색을 하나의 탭으로 합치지 않는다.
- 하위 화면에서는 공통 상단 헤더와 뒤로가기를 사용한다.
- 탭 바는 콘텐츠보다 시각적으로 조용하게 유지한다.
- 스크롤 중 탭 바의 기존 자동 숨김 동작을 보존한다.

## 5. 핵심 사용자 흐름

### 5.1 랜덤 번호 생성

```text
[번호뽑기]
→ 게임 수 선택
→ 랜덤으로 뽑기
→ 번호 공개
├→ 내 번호에 자동 저장
└→ 조합 분석
```

무작위 생성 결과는 추천이나 당첨 가능성 평가가 아니다.

### 5.2 조건 기반 생성

```text
[번호뽑기]
→ 조건 뽑기
→ 조건 선택·수정
→ 조합 생성
→ exact 또는 nearest 결과
├→ 내 번호에 자동 저장
├→ 같은 조건으로 다시 뽑기
└→ 조합 분석
```

조건은 사용자의 형태 선호를 반영한다. 조건을 만족하는 조합을 찾지 못하면 가장 가까운 결과와 불일치 조건을 설명한다.

### 5.3 내 번호 관리

```text
[내번호보기]
→ 전체 / 구매번호 / 즐겨찾기
→ 저장된 조합 선택
├→ 구매 표시 변경
├→ 즐겨찾기 변경
├→ 같은 조건으로 다시 뽑기
└→ 조합 분석
```

### 5.4 번호별 통계 탐색

```text
[통계보기]
→ 번호별 통계
→ 1–45 스크러버 탐색
├→ 기간·보너스 조건 변경
├→ 출현 기록 상세
├→ 45개 번호 비교
└→ 선택 번호를 조합 초안에 추가
```

### 5.5 당첨번호 분석

```text
[통계보기]
→ 당첨번호 분석
→ 회차 선택 또는 이전·다음 회차 이동
→ 이 회차 분석하기
→ 선택 회차의 본번호 6개 분석
├→ 기간·보너스 조건 변경
├→ 전체/등위별 기록
└→ 다른 회차 보기
```

당첨번호 분석은 선택한 역사적 회차의 여섯 본번호를 기존 조합 분석 기준으로 다시 살펴보는 기능이다. 해당 회차의 보너스 번호는 회차 정보로 표시하되 분석 대상 여섯 번호에는 포함하지 않는다. AI 해설과 내 번호 저장 동작은 노출하지 않는다.

### 5.6 직접 선택한 조합 분석

```text
[통계보기]
→ 조합 분석
→ 번호 6개 직접 선택
→ 분석하기
→ 분석 결과
├→ 기간·보너스 조건 변경
├→ 전체/등위별 기록
├→ 하위 조합 전체 보기
├→ 다른 조합과 비교
└→ 새로하기
```

통계보기에서 직접 선택할 때는 랜덤 채우기를 노출하지 않는다. 여섯 번째 번호를 선택해도 자동으로 분석을 시작하지 않는다.

### 5.7 생성·보관함에서 조합 분석

생성 결과나 내번호보기에서 진입하면 전달된 여섯 번호를 분석 대상으로 사용한다. `새로하기`는 이전 유입 화면과 무관하게 빈 직접 선택 화면으로 돌아간다.

## 6. 화면 1 — 번호뽑기

### 6.1 목적

사용자가 무작위 또는 직접 선택한 조건으로 번호 조합을 만들고 분석 흐름으로 이어가게 한다.

### 6.2 번호뽑기 홈

주요 구성:

- 조건 뽑기 주요 카드
- 최신 회차 번호와 보너스 번호
- 다음 추첨까지 남은 시간
- 랜덤조합 게임 수 선택
- 생성 번호가 추천이 아니라는 안내

기본 기능 공개 상태에서는 최대 5게임까지 선택할 수 있다. Pro 기능을 운영할 때의 게스트·Pro 차이는 회원 정책 문서를 따른다.

### 6.3 랜덤조합

- 1–45에서 중복 없이 6개를 생성한다.
- 여러 게임을 요청하면 게임 간 동일 조합을 중복 생성하지 않는다.
- 섞기와 번호 공개 모션은 결과 이해를 돕는 범위로 제한한다.
- 생성 완료 후 조합을 내 번호에 저장한다.
- 각 게임을 개별적으로 분석할 수 있다.

### 6.4 조건 뽑기

현재 지원하는 조건 범주는 다음과 같다.

- 고정수와 제외수
- 번호 합계, 끝수 합계, 표준편차
- 홀짝, 저고, A/C 값
- 소수, 완전제곱수, 합성수
- 3·4·5의 배수
- 이월수, 이웃수
- 연속수 형태, 동끝수 형태
- 번호대별 개수
- 과거 1·2·3등 조합 제외

생성 결과는 다음 정보를 유지한다.

- 생성 번호
- 적용 조건 요약
- exact / nearest 상태
- nearest일 때 충족하지 못한 조건
- 같은 조건 재생성에 필요한 조건 스냅샷

`추천 조건`이라는 UI 표현은 당첨 번호 추천이 아니라 미리 구성한 조건 프리셋을 의미해야 한다. 사용자에게 확률 우위로 읽힐 표현은 사용하지 않는다.

## 7. 화면 2 — 내번호보기

### 7.1 목적

생성하거나 직접 분석한 번호를 다시 찾고 상태를 관리한다.

### 7.2 기본 동작

- 저장 조합을 최신순으로 표시한다.
- 최대 보관 개수는 현재 구현 상 200개다.
- `전체`, `구매번호`, `즐겨찾기` 필터를 제공한다.
- 생성 출처와 저장 시각을 표시한다.
- 조건 생성 결과는 적용 조건을 함께 표시한다.
- 구매 표시와 즐겨찾기는 서로 독립적이다.
- 저장된 조합에서 조합 분석으로 이동할 수 있다.
- 생성 조건이 있는 조합은 같은 조건으로 다시 뽑을 수 있다.

### 7.3 저장 정책

- 기본 사용자는 현재 기기의 AsyncStorage에 저장한다.
- Pro 및 연결 계정 조건을 만족하면 Firestore 저장과 기기간 동기화를 사용할 수 있다.
- 클라우드 모드 진입 시 기기 데이터를 사용자 저장소로 마이그레이션한다.
- Firebase가 없어도 기기 저장 기능은 유지한다.

## 8. 화면 3 — 통계보기

### 8.1 통계 허브

다음 네 경험의 진입점을 제공한다.

1. 번호별 통계
2. 당첨데이터 종합 통계
3. 당첨번호 분석
4. 조합 분석

모든 통계는 과거 데이터에 대한 설명이며 미래 당첨 가능성을 뜻하지 않는다는 공통 안내를 제공한다.

### 8.2 번호별 통계

한 번호를 분석 단위로 사용한다.

현재 주요 기능:

- Magnetic Fisheye NumberScrubber
- 기간 및 보너스 포함 필터
- 출현 횟수·출현율·출현 순위
- HOT / NEUTRAL / COLD
- 최근 흐름
- 평균·현재·최대 미출현 간격
- Pair / Trio
- 출현 기록 상세
- 45개 번호 비교
- 선택 번호를 조합 초안에 추가

스크러버 LEFT와 분석 RIGHT는 독립적으로 스크롤한다. 터치, 플릭, 마우스 휠, 트랙패드를 지원하며 입력 중인 영역이 다른 영역의 스크롤을 움직이지 않아야 한다.

### 8.3 당첨데이터 종합 통계

전체 과거 회차를 조합 단위로 요약한다.

현재 주요 분석:

- 1–45 번호 출현 분포와 상위 번호
- 동끝수 형태
- 번호 합계, 끝수 합계, 표준편차 구간
- 홀짝 및 저고 비율
- A/C 값
- 소수, 완전제곱수, 합성수 개수
- 배수 개수
- 이월수, 이웃수, 연속수 형태
- 번호대별 개수

분포는 과거 조합의 모양을 설명할 뿐, 특정 형태를 추천하지 않는다.

### 8.4 당첨번호 분석

역사적 회차 하나를 골라 그 회차의 여섯 본번호를 기존 조합 분석과 같은 기준으로 분석한다.

현재 주요 기능:

- 기본값은 최신 회차
- 회차 직접 입력
- 최근 회차 목록 선택
- 이전·다음 회차 이동
- 회차 본번호와 보너스 번호 표시
- 기간·보너스 분석 필터
- 조합 분석 결과와 전체/등위별 상세 기록
- 결과에서 다른 회차로 전환

이 기능은 역사적 당첨 조합의 과거 맥락을 설명한다. 같은 조합이나 형태의 미래 출현을 예측하지 않는다.

### 8.5 조합 분석

정확히 여섯 번호를 분석 단위로 사용한다.

입력 방식:

- 통계보기에서 1–45 직접 선택
- 번호뽑기 결과에서 전달
- 내번호보기의 저장 조합에서 전달
- 번호별 통계의 조합 초안에서 전달

직접 선택 규칙:

- 6개 미만이면 `분석하기` 비활성
- 7번째 번호 선택 불가
- 여섯 번째 선택 후 자동 분석 금지
- 분석 번호는 오름차순 정규화

결과 구성:

- 선택한 여섯 번호와 대표 설명
- 최고 본번호 일치 수
- 1–5등 기록 요약
- 0–6개 본번호 일치 분포
- 선택 번호 평균과 전체 45개 평균 비교
- 번호별 출현 횟수와 순위
- 조합 형태 및 조건별 통계
- 2–6개 하위 조합 빈도
- 전체/등위별 일치 기록 상세
- 2–4개 하위 조합 전체 목록
- A/B 조합 비교
- 조건 충족 시 AI 조합 해설

`새로하기`는 번호를 모두 지우고 직접 선택 상태로 돌아간다. 분석 결과에서 번호를 제자리 수정하는 기능은 제공하지 않는다.

## 9. 조합 분석 데이터 정의

### 9.1 기간 필터

- 최근 3회
- 최근 5회
- 최근 10회
- 최근 52회
- 전체
- Custom

기간 변경 시 모든 기간 의존 값이 같은 범위로 갱신되어야 한다. Custom 사용 가능 여부는 현재 상품 접근 정책을 따른다.

### 9.2 보너스 분석 필터

보너스 필터는 일반 출현·동시 출현 통계에만 적용한다.

- OFF: 여섯 본번호만 사용
- ON: 승인된 분석 정의에 따라 역사적 보너스 번호 포함

등수 기록과 본번호 일치 분포는 이 UI 필터의 영향을 받지 않는다.

### 9.3 등수 판정

- 본번호 6개 일치 → 1등
- 본번호 5개 + 해당 회차 보너스 일치 → 2등
- 본번호 5개, 보너스 불일치 → 3등
- 본번호 4개 일치 → 4등
- 본번호 3개 일치 → 5등
- 그 외 → 등위 없음

화면에서는 `1등`부터 `5등`까지 그대로 표시하고 등수 뒤에 별도의 완곡어를 붙이지 않는다. 실제 구매나 당첨을 의미하지 않는다는 안내는 결과 화면의 설명 문구로 분리한다.

### 9.4 본번호 일치 분포

선택 기간의 각 회차에 대해 선택 번호와 여섯 본번호가 0–6개 중 몇 개 일치하는지 센다. 보너스 번호는 포함하지 않는다.

### 9.5 하위 조합

선택한 여섯 번호의 모든 비순서 조합을 생성한다.

| 크기 | 조합 수 |
|---|---:|
| 2개 | 15 |
| 3개 | 20 |
| 4개 | 15 |
| 5개 | 6 |
| 6개 | 1 |

기본 정렬:

1. 출현 횟수 내림차순
2. 최근 출현 회차 내림차순

0회 조합을 의미 있는 TOP 결과처럼 표현하지 않는다. 필요한 경우 `선택 범위에서 동시 출현 기록이 없습니다.`를 사용한다.

### 9.6 선택 번호 그룹 빈도

- 선택한 6개 번호의 평균 출현 횟수
- 전체 45개 번호의 평균 출현 횟수
- 전체 평균 대비 차이율

이 값은 서술형 비교이며 좋음·나쁨·행운·유리함으로 분류하지 않는다.

## 12. 인증·저장·클라우드 정책

### 12.1 사용자 상태

| 상태 | 설명 |
|---|---|
| guest | Firebase 없이 로컬에서 사용하는 상태 |
| anonymous | Firebase 익명 UID가 있는 상태 |
| authenticated | Apple 또는 Google 계정이 연결된 상태 |

익명 인증은 회원가입 요구가 아니라 서버 요청, 구매 권한, 계정 전환 전 데이터를 같은 사용자로 묶기 위한 내부 식별 수단이다.

### 12.2 저장 모드

| 조건 | 저장 위치 |
|---|---|
| 기본 또는 미연결 사용자 | 현재 기기 |
| Pro + 연결 계정 | Firestore 클라우드 |

핵심 기능은 클라우드 저장에 의존하지 않는다.

### 12.3 개인정보 원칙

- Analytics가 활성화되면 선택·생성한 번호 조합, 조합 키와 홀짝·합계 등의 요약값이 이용 이벤트로 기록될 수 있다.
- 이름, 이메일, Firebase UID와 광고 식별자 원문은 커스텀 Analytics 이벤트 파라미터로 보내지 않는다.
- AI 자유 입력 질문, 선택 번호와 분석 맥락은 사용자가 AI 해설을 요청할 때 답변 생성을 위해 서버와 AI 제공자에 전송될 수 있다.
- 익명 UID도 개인정보처리방침과 삭제 안내 대상에 포함한다.
- 계정 삭제는 인증 데이터, 사용자 저장 데이터, 연동된 구매 고객 데이터의 처리 범위를 명확히 안내한다.

## 18. 현재 결정 필요 사항

1. **Pro 운영 시 조건 선택 한도**

   현재 코드는 게스트 99개, Pro 무제한이다. 과거 문서의 2개 제한으로 되돌릴지, 다른 Pro 가치를 사용할지 결정한다.

2. **운영 광고 단위와 스토어 선언**

   현재 결정한 광고 기반 무료 운영을 위해 iOS·Android 운영 광고 단위, 개인정보 동의와 스토어 데이터 공개 항목을 검증한다.

3. **AI 플래그와 서버 권한 일치**

   Pro 플래그 OFF에서는 클라이언트 접근 정책이 AI를 열 수 있지만 현재 서버 함수는 항상 실제 Pro 권한을 요구한다. 기본 공개 빌드에서 AI를 숨길지, 별도 AI 플래그를 둘지 결정한다.

4. **`추천 조건` 명칭**

   조건 프리셋임을 명확히 하기 위해 `균형 조건`, `기본 조건` 등의 대체 명칭을 검토한다.

5. **5개·6개 하위 조합 상세 진입**

   계산 결과는 존재하지만 메인 결과에서 전체 목록 진입은 현재 2–4개 조합에 집중되어 있다.

6. **콘텐츠 운영 방식**

   앱 릴리스에 묶인 정적 콘텐츠를 유지할지, 별도 배포 가능한 콘텐츠 시스템을 도입할지 후속 검토한다.

7. **직접 선택 조합의 클라우드 저장 규칙**

   앱 보관함은 `manual` 출처를 지원하지만 현재 Firestore 규칙의 허용 출처는 `ai`, `random`이다. 계정·클라우드 기능을 켜기 전에 저장 모델과 보안 규칙을 일치시킨다.

8. **조건 생성 출처 명칭**

   현재 내부 저장 모델은 조건 생성 조합에 `ai` 출처 값을 사용한다. 사용자 화면의 조건 뽑기가 AI 번호 추천으로 오해되지 않도록 내부 명칭을 유지할지 `condition`으로 마이그레이션할지 검토한다.
