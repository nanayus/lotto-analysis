# 사용자 상태 및 상품 접근 정책

작성 기준일: 2026-09-06

## 1. 정책 목적

Lotto Insight에서는 **인증 상태**, **상품 등급**, **저장 방식**을 서로 다른 개념으로 다룬다.

- 인증 상태: guest / anonymous / authenticated
- 상품 등급: guest / Pro
- 저장 방식: device / cloud

로그인했다고 Pro가 되지 않으며, Pro를 구독했다고 Apple·Google 계정 연결이 필수인 것도 아니다.

## 2. 현재 기본 배포

현재 기본 환경은 다음과 같다.

- `EXPO_PUBLIC_PRO_PLAN_ENABLED=false`
- `EXPO_PUBLIC_RESULT_ADS_ENABLED=true`
- `EXPO_PUBLIC_ACCOUNT_LINKING_ENABLED=false`
- `EXPO_PUBLIC_ANONYMOUS_AUTH_ENABLED=false`
- 생성·분석 핵심 기능 전체 공개
- 지원되는 네이티브 환경에서 결과 전면광고 운영
- Pro 결제 및 잠금 UI 비활성
- 계정 연결 UI 비활성
- 내 번호는 현재 기기에 저장
- 앱 실행 시 Firebase 익명 UID를 생성하지 않음

따라서 기본 배포에서 사용자는 회원가입이나 결제 없이 모든 핵심 기능을 이용하며, 분석 결과를 열 때 광고를 볼 수 있다. 광고가 구성되지 않았거나 로드에 실패한 경우에는 결과를 차단하지 않는다.

## 3. 인증 상태

| 상태 | 의미 | 사용자 경험 |
|---|---|---|
| guest | Firebase가 없거나 초기화되지 않은 로컬 사용자 | 핵심 기능과 기기 저장 사용 |
| anonymous | 익명 인증 플래그를 다시 켰을 때 Firebase 익명 UID가 있는 사용자 | 현재 배포에서는 생성하지 않음 |
| authenticated | Apple 또는 Google 계정이 연결된 사용자 | 조건 충족 시 클라우드 동기화와 계정 복원 가능 |

현재는 모든 기능을 무료로 공개하고 Pro 구매도 운영하지 않으므로 익명 사용자 식별이 필요하지 않다. 기존 익명 인증 코드는 향후 서버 권한·구매 복원이 필요할 때 다시 사용할 수 있도록 보존한다.

## 4. 상품 등급

| 등급 | 의미 |
|---|---|
| guest | 구독이 없거나 Pro 운영이 비활성인 기본 등급 |
| Pro | RevenueCat 또는 서버 권한으로 활성 상태가 확인된 구독 등급 |

상품 등급은 인증 제공자와 무관하다.

## 5. Pro 기능을 활성화했을 때의 현재 코드 정책

| 항목 | 게스트 | Pro |
|---|---|---|
| 분석 결과 | 전면광고 경로 | 즉시 공개 |
| 같은 조합 재열람 | 전면광고 경로 | 즉시 공개 |
| 한 번에 생성할 조합 | 최대 2개 | 최대 5개 |
| 직접 선택할 생성 조건 | 현재 코드상 최대 99개 | 무제한 |
| 균형 프리셋 | 불가 | 가능 |
| AI 조합 해설 | 불가 | 가능 |
| 같은 조건으로 다시 뽑기 | 불가 | 가능 |
| Custom 분석 기간 | 불가 | 가능 |
| 내 번호 저장 | 현재 기기 | 현재 기기, 연결 계정은 클라우드 |
| 기기간 동기화 | 불가 | 연결 계정에서 가능 |

과거 정책의 `게스트 조건 최대 2개`는 현재 구현과 일치하지 않는다. Pro 운영 전에 99개 제한을 유지할지, 다른 제한이나 혜택으로 교체할지 제품 결정을 완료해야 한다.

현재는 Pro 플랜을 활성화하지 않으므로 위 차이는 사용자에게 노출되지 않는다. 모든 사용자는 Pro 전용으로 설계했던 기능을 무료로 사용하되, AI 해설은 서버 비용과 권한 정책 때문에 UI를 숨긴다.

## 6. 저장 정책

- 모든 사용자는 기본적으로 번호를 현재 기기에 저장할 수 있다.
- Pro이면서 Apple·Google 계정을 연결한 경우 클라우드 저장을 사용할 수 있다.
- 연결되지 않은 Pro 사용자는 기기 저장을 계속 사용한다.
- 클라우드 모드 전환 시 기기 저장 데이터를 사용자 저장소로 마이그레이션한다.
- 로그인 또는 Pro 상태가 핵심 통계 계산의 전제 조건이 되어서는 안 된다.

## 7. 게스트 UX

- 가입이나 로그인 없이 핵심 기능을 바로 사용한다.
- 번호와 즐겨찾기는 현재 기기에 저장한다.
- Pro가 비활성인 현재 배포에서는 기능 잠금 없이 사용하고 결과 진입 시 전면광고를 표시한다.
- 광고 미구성·로드 실패 시 결과를 그대로 공개한다.
- Pro가 활성화된 운영 배포에서는 결과 진입과 잠금 기능 자리에서만 짧은 안내를 제공한다.
- 한 화면에서 같은 Pro 혜택을 반복 설명하지 않는다.

## 8. Pro UX

현재는 사용자에게 노출하지 않는다. 아래 내용은 Pro 판매를 재개할 때 복구할 정책이다.

- 광고 없이 결과를 바로 본다.
- 최대 5개 조합을 한 번에 생성한다.
- 조건을 제한 없이 사용하고 균형 프리셋을 사용할 수 있다.
- AI 해설, 같은 조건으로 다시 뽑기, Custom 기간을 사용할 수 있다.
- 계정을 연결하면 저장한 번호를 클라우드에 보관하고 기기간 동기화한다.

## 9. 로그인 역할

- 현재는 익명 인증과 Apple·Google 계정 연결을 모두 비활성화한다.
- 익명 인증을 다시 켜면 로그인 화면 없이 서버 요청과 구매 권한을 사용자별로 구분할 수 있다.
- Apple·Google 계정 연결은 클라우드 동기화와 앱 데이터 복원을 위한 선택 기능이다.
- Apple·Google 로그인은 Pro 구독 조건이 아니다.
- 로그인 화면에서 기능 한도 증가나 당첨 관련 혜택을 약속하지 않는다.
- 과거 연결 계정의 삭제 경로와 관련 구현은 코드에 유지한다.

## 10. 문구 원칙

- 상품 등급은 `FREE` 또는 `PRO` 상태로 표시한다.
- 인증 상태를 상품 등급처럼 표현하지 않는다.
- `로그인하면 Pro`, `가입하면 분석 증가`와 같은 문구를 사용하지 않는다.
- 잠금 시점에만 제한과 Pro 혜택을 짧게 설명한다.
- 생성과 분석이 예측이나 추천이 아니라는 원칙을 유지한다.

## 11. 현재 비활성 기능

| 기능 | 현재 상태 | 복구 플래그 또는 조건 |
|---|---|---|
| Pro 결제·구매 복원 | 비활성 | `EXPO_PUBLIC_PRO_PLAN_ENABLED=true` 및 RevenueCat 운영 설정 |
| Pro 배지·구매 안내·기능 잠금 | 비활성 | `EXPO_PUBLIC_PRO_PLAN_ENABLED=true` |
| AI 조합 해설 | UI 비활성 | Pro, Functions, AI 비용·권한 정책 검증 |
| Apple·Google 계정 연결 | 비활성 | `EXPO_PUBLIC_ACCOUNT_LINKING_ENABLED=true` |
| Firebase 익명 인증 | 비활성 | `EXPO_PUBLIC_ANONYMOUS_AUTH_ENABLED=true` |
| 초대 코드 | 비활성 | 익명 또는 연결 계정 식별과 서버 정책 필요 |
| 클라우드 저장·기기간 동기화 | 비활성 | 계정 연결과 Firestore 운영 검증 |

현재 활성 수익 기능은 지원되는 네이티브 환경의 결과 전면광고뿐이다. Firebase Analytics는 로그인이나 익명 인증과 무관하게 계속 운영할 수 있다.

## 12. 활성화 전 확인 사항

- 게스트 조건 선택 한도 최종 결정
- App Store·Google Play 상품 및 가격
- RevenueCat Offering, entitlement, 구매 복원
- AdMob 전면광고와 실패 대체 흐름
- 익명 사용자 구매 복원 시나리오
- 계정 연결 전후 저장 데이터 마이그레이션
- 직접 선택 조합 `manual` 출처와 Firestore 허용 규칙 일치
- 개인정보처리방침과 계정 삭제
