# 수익화 구현 기준

작성 기준일: 2026-09-06

## 1. 기능 플래그

기능 공개와 결제는 `EXPO_PUBLIC_PRO_PLAN_ENABLED`, 결과 광고는 `EXPO_PUBLIC_RESULT_ADS_ENABLED`로 각각 제어한다.

| 플래그 | 동작 |
|---|---|
| Pro `false` | 모든 핵심 기능 공개, 결제·잠금 UI 비활성 |
| Pro `true` | 서버·RevenueCat 권한에 따라 guest / Pro 정책 적용 |
| 결과 광고 `false` | 결과를 광고 없이 공개 |
| 결과 광고 `true` | 광고가 구성된 환경에서 결과 진입 전 전면광고 사용 |

계정 연결 UI는 별도의 `EXPO_PUBLIC_ACCOUNT_LINKING_ENABLED` 플래그로 제어한다.

수익화와 계정 연결을 같은 플래그나 같은 사용자 상태로 취급하지 않는다.

## 2. 접근 모델

```ts
type AccountTier = 'guest' | 'pro';
```

인증 상태와 상품 등급을 분리한다. 인증된 비구독 계정도 상품 접근 권한은 `guest`다.

Pro 플래그를 활성화했을 때의 현재 코드 값:

| 권한 | guest | pro |
|---|---:|---:|
| `combinationSelectionLimit` | 2 | 5 |
| `conditionSelectionLimit` | 99 | `null` |
| `requiresAdForResults` | `true` | `false` |
| `canUseBalancedPreset` | `false` | `true` |
| `canUseAiExplanation` | `false` | `true` |
| `canRegenerateWithSameConditions` | `false` | `true` |
| `canUseCustomPeriod` | `false` | `true` |
| `canSaveNumbers` | `true` | `true` |
| `storageMode` | `device` | `device`, 연결 계정은 `cloud` |

`conditionSelectionLimit=99`는 현재 구현을 기록한 값이다. 기존 2개 제한을 의미하지 않는다. 운영형 Pro를 켜기 전에 이 값을 최종 상품 정책으로 유지할지 결정한다.

## 3. 결과 공개

```text
분석 요청
├─ Pro 또는 Pro 플래그 OFF → 바로 결과 계산·표시
└─ Guest + Pro 플래그 ON → 전면광고 닫힘 → 결과 계산·표시
```

- 동일 조합을 내 번호에서 다시 열 때도 같은 접근 검사를 실행한다.
- 광고가 준비되지 않았거나 표시되지 못한 경우의 대체 흐름을 명시적으로 제공한다.
- 광고 상태가 핵심 분석을 영구 차단해서는 안 된다.

## 4. 조건 선택

- Pro 플래그 OFF에서는 조건 선택과 균형 프리셋 등 핵심 기능을 공개한다.
- Pro 플래그 ON에서 게스트의 현재 코드상 조건 한도는 99개다.
- 기존 조건을 끄는 동작은 항상 허용한다.
- Pro는 조건 수 제한 없이 균형 프리셋을 사용할 수 있다.
- Pro가 조건 선택 화면에 진입하면 추천 조건 적용 여부를 한 번 물을 수 있다.
- `직접 설정`은 현재 조건을 유지하고, `적용`은 정의된 프리셋 조건을 설정한다.
- `추천 조건`은 번호 추천이 아니라 조건 프리셋이라는 의미가 명확해야 한다.
- 조건 화면 진입만으로 자동 결제 안내를 띄우지 않는다.

## 5. 저장

- 모든 사용자는 번호를 공용 기기 저장 키에 보관할 수 있다.
- 기존 사용자별 기기 데이터가 있으면 공용 기기 저장으로 병합한다.
- 익명 Pro는 기기 저장을 유지한다.
- Pro 사용자가 Apple·Google 계정을 연결하면 기기 데이터를 클라우드 데이터와 병합한다.
- 저장, 구매 표시, 즐겨찾기는 로그인 없이 사용할 수 있다.
- 보관함은 `manual` 출처를 지원하지만 현재 Firestore 규칙은 `ai`, `random`만 허용한다. 계정·클라우드 기능을 활성화하기 전에 데이터 모델과 규칙을 일치시킨다.

## 6. 같은 조건으로 다시 뽑기

- 조건 뽑기로 만든 조합의 분석 결과와 내 번호에 기능을 표시한다.
- Pro 플래그 OFF에서는 기능을 바로 사용할 수 있다.
- Pro 플래그 ON의 게스트에게는 잠금과 Pro 안내를 제공한다.
- 사용 가능 상태에서는 저장된 생성 조건으로 새 조합을 만든다.
- 생성 중에는 기존 로딩 흐름을 보여준 뒤 같은 분석 결과 화면으로 이어간다.

## 7. AI 조합 해설

- 표준 분석 보고서를 대체하지 않는 선택 기능이다.
- Pro 플래그 OFF에서는 현재 클라이언트 접근 정책상 카드가 열릴 수 있지만, 서버 함수는 플래그와 무관하게 실제 Pro 권한을 요구한다.
- Pro 플래그 ON에서는 클라이언트 잠금과 서버의 Pro 재검증을 모두 사용한다.
- 확정된 분석 스냅샷과 사용자 질문만 해설 입력으로 사용한다.
- 미래 번호, 당첨 가능성, 유리한 조합 요청에는 응답하지 않는다.
- 자유 입력 질문은 Analytics 이벤트로 보내지 않지만 AI 요청 처리를 위해 서버와 AI 제공자에 전달될 수 있다.
- 따라서 기본 공개 빌드에서 AI를 노출하려면 서버 정책을 함께 바꾸고 검증해야 하며, 그렇지 않으면 AI를 단계적 활성화 기능으로 유지한다.

## 8. 화면 문구

- 플래그 OFF: `조건 무제한 · 추천 조건`
- Pro: `Pro · 조건 무제한 · 추천 조건`
- 게스트 결과: `광고 보고 이번 결과 보기`
- Pro 결과: 즉시 결과 보기
- 기기 저장: `이 기기에만 저장돼요`
- 클라우드 저장: `클라우드에 저장되어 다른 기기와 동기화돼요`

`무료회원`, `티켓`, `분석권`, `로그인하면 Pro`, `로그인하면 당첨 확률 증가` 문구를 사용하지 않는다.

## 9. 상단 플랜 배지

- Pro 플래그가 활성일 때 현재 등급만 `FREE` 또는 `PRO`로 표시한다.
- FREE는 중립 표면, PRO는 강조 표면과 글자색으로 구분한다.
- FREE 배지는 공통 Pro 안내를 열고, PRO 배지는 이용 기간 정보창을 연다.
- `proExpiresAt`이 유효할 때만 만료일을 표시한다.
- 인증 상태를 상품 등급 배지에 섞지 않는다.

## 10. 필수 테스트

### 광고 기반 무료 빌드

1. 결제 안내나 기능 잠금 없이 모든 생성·분석 기능을 사용할 수 있다.
2. 광고가 구성된 네이티브 환경에서는 결과 진입 전에 전면광고가 표시된다.
3. 광고가 없거나 실패해도 결과를 볼 수 있다.
4. 최대 5개 조합과 조건 기능을 사용할 수 있다.
5. 번호가 기기에 저장되고 다시 열린다.
6. Firebase가 없어도 핵심 기능이 동작한다.

### Pro 활성 빌드

1. 게스트는 최대 2개, Pro는 최대 5개 조합을 생성한다.
2. 현재 정책값에 따라 게스트 조건 최대 99개가 적용된다.
3. 게스트의 신규 분석과 재열람이 광고 흐름을 거친다.
4. Pro는 광고 없이 결과를 본다.
5. 계정 연결만으로 guest 한도가 늘어나지 않는다.
6. 익명 구매와 구매 복원이 Pro로 반영된다.
7. 익명 Pro는 기기 저장, 연결 계정 Pro는 클라우드 저장을 사용한다.
8. 같은 조건 다시 뽑기, AI, Custom, 균형 프리셋의 접근 차이가 정확하다.
9. 서버가 AI 해설과 권한 요청에서 Pro 상태를 재검증한다.
10. 광고·구매·서버 실패 시 사용자에게 복구 가능한 상태를 제공한다.
