# 수익 모델 구현 기준

## 접근 모델

```ts
type AccountTier = 'guest' | 'pro';
```

인증 상태와 상품 등급을 분리한다. 인증된 비구독 계정도 상품 접근 권한은 `guest`다.

| 권한 | guest | pro |
|---|---:|---:|
| `combinationSelectionLimit` | 2 | 5 |
| `conditionSelectionLimit` | 2 | `null` |
| `requiresRewardedAdForResults` | `true` | `false` |
| `canUseBalancedPreset` | `false` | `true` |
| `canUseAiExplanation` | `false` | `true` |
| `canRegenerateWithSameConditions` | `false` | `true` |
| `canUseCustomPeriod` | `false` | `true` |
| `storageMode` | `device` | `cloud` |

## 결과 공개

```text
분석 요청
├─ Pro → 바로 결과 계산·표시
└─ Guest → 리워드 광고 완료 → 결과 계산·표시
```

동일 조합을 내 번호에서 다시 열어도 같은 접근 검사를 실행한다. 결과를 본 적이 있다는 이유로 게스트 광고를 생략하지 않는다.

## 조건 선택

- 게스트 기본 조건은 2개까지 활성화한다.
- 한도에 도달하면 아직 선택하지 않은 스위치는 비활성화한다.
- 비활성 스위치를 누르면 간결한 제한 팝업을 연다.
- 기존 조건을 끄는 동작은 항상 허용한다.
- Pro는 조건 수 제한이 없고 균형 프리셋을 명시적으로 눌러 적용한다.
- Pro가 조건 선택 화면에 진입하면 추천 조건을 바로 적용할지 한 번 묻는다.
- `직접 설정`을 고르면 현재 조건을 유지하고, `적용`을 고르면 6개 추천 조건을 설정한다.
- 게스트에게는 조건 화면 진입만으로 자동 상품 안내 팝업을 띄우지 않는다.

## 저장

- 게스트 번호는 공용 기기 저장 키에 보관한다.
- 기존 로그인 사용자별 기기 저장 데이터가 있으면 공용 기기 저장으로 병합한다.
- Pro 전환 시 기기 데이터를 클라우드 데이터와 병합한다.
- 게스트는 저장·구매 표시·즐겨찾기를 로그인 없이 사용할 수 있다.

## 같은 조건으로 다시 뽑기

- 조건 뽑기로 만든 조합의 분석 결과와 내 번호에 기능을 표시한다.
- 게스트에게도 버튼과 `PRO` 잠금을 보여주고, 누르면 Pro 안내를 연다.
- Pro가 누르면 저장된 생성 조건으로 새 조합을 만든다.
- 생성 중에는 기존 로또 볼 로딩 화면을 보여준 뒤 같은 분석 결과 화면으로 이어간다.

## 화면 문구

- 조건 상단: `Pro · 조건 무제한 · 균형 프리셋`
- 조건 제한: `조건은 2개까지 선택할 수 있어요`
- 게스트 결과: `광고 보고 이번 결과 보기`
- Pro 결과: 즉시 결과 보기
- 기기 저장: `이 기기에만 저장돼요`

`무료회원`, `티켓`, `분석권`, `로그인하면 조건 5개` 문구를 사용하지 않는다.

## 필수 테스트

1. 게스트 조건 세 번째 스위치가 비활성화되고 Pro 팝업이 열린다.
2. Pro는 세 번째 이상의 조건을 선택할 수 있다.
3. 게스트 진입 시 자동 팝업이 없고, Pro 진입 시 추천 조건 확인창이 한 번 열린다.
4. 게스트도 번호를 기기에 저장하고 다시 볼 수 있다.
5. 게스트의 새 분석과 재열람 모두 광고 흐름을 거친다.
6. Pro는 광고 없이 결과를 본다.
7. 로그인만으로 게스트 한도가 늘어나지 않는다.
8. 게스트의 같은 조건 다시 뽑기는 Pro 안내로 연결되고, Pro는 로딩 후 새 결과를 본다.
